    00 What Agentstakk caught while we were building capy

    "I took the shortcut."
    — your LLM

    Three /kk:review-code runs on the same capy diff. Each time, the agent read the code first and got to the review checklists late or not at all. In the third run it was told to "follow the review process exactly". It loaded 28 files and still read the diff first. The skill itself said to start with the diff, so the fix was to change the order, not to write a sterner prompt.

    capy (https://github.com/serpro69/capy) is a local MCP server, written in Go, that keeps large outputs out of a coding agent's context window. It was built from start to finish with Agentstakk: skills, sub-agents and config for Claude Code and Codex, run as /kk: commands from design through review, tests and docs. Below is what they caught along the way, quoted from capy's own records. Nothing is staged.

    Left behind All 16 skills now load their method before they touch your code. From `review-code/SKILL.md`: "The standard workflow below is strictly sequential."

    From the same record: "Enforcement is convention, not mechanism."

    01/05 Design

    One reader handled a new line type. The other two silently dropped it.

    capy's session vault read Claude transcripts with three separate readers: one for search, one for `show`, one for the terminal viewer. capy's knowledge base had a recurring bug on record: a new line type handled in one reader was silently lost from the other two. The plan to add Codex sessions cited that record and didn't add three more readers. It replaced them with one decoder per format.

    Before any of the old reader code changed, Task 1 recorded what those readers produced for every session file on the machine, 700 of them. Every later task had to match that output byte for byte. The final /kk:test run compared 698 and found 0 mismatches.

    Left behind ADR-031: "A new line type is handled once, in the decoder; the "three parsers must stay in sync" convention is retired." And `TestGolden_CoversEveryLineType`, which "enforces the one-case-per-arm rule mechanically".

    02/05 Design review

    This upgrade would have stopped every existing vault from opening.

    The same plan then went through four separate /kk:review-design runs before any code existed. Two of them found that a new index ran before the migration that creates its column. On any existing vault, that fails at open. The same pass found that merging an old vault would silently drop about 1 in 11 sessions.

    Every claim was re-checked against the code and the real session files on the machine before the plan changed. The design was revised on 2026-09-13; the code landed two days later.

    Left behind An invariant in the implementation plan: "`schemaSQL` may therefore reference only columns that exist in every historical schema." And `TestMigrate0006_LegacyVaultOpensThroughStore`, which opens a pre-migration vault through the store.

    03/05 Code review

    A symlinked folder and .. walked straight past the deny list.

    capy checks file paths against deny rules, so an agent can't route a read of something like ~/.ssh/id_rsa through it. The first version tidied each path before resolving symlinks. Tidying turns dir-link/../secrets into `secrets`, so the symlinked folder vanishes from the check. The OS doesn't tidy: it follows dir-link first, then `..`, and can end up inside a denied folder.

    The isolated review rated it P0. It was fixed in the same task, with a regression test, and the finding went into capy's knowledge base, where later reviews search it.

    Left behind The regression test `physical traversal via symlinked dir caught`, and the finding indexed as `kk:review-findings`.

    04/05 Code review

    The tests could chmod a developer's real key file.

    A capy change made setup repair the permissions on database key files. The full test suite passed. Then a fresh reviewer agent, one that hadn't written the code, noticed that the existing setup tests read the developer's global config. After this change, running them could change the permissions on the developer's real key.

    The external model reviewing alongside it reported no issues and claimed protections the code didn't have. The record says so and doesn't adopt them.

    Left behind The tests now isolate global config in `TestMain`. A probe with a deliberately loose 0644 key file "left that file at `0644`". The non-atomic repair is recorded as a known limit, with the hardening steps written down.

    05/05 Spec review

    The live tests passed. None of them exercised the default wait.

    capy_execute waits up to 25 seconds, then hands back a "still running" receipt so the agent isn't stuck. The live acceptance runs on real Claude Code and Codex hosts all passed. But they were short commands with the wait raised to 30 seconds, so none of them ever hit the default.

    The closing spec review caught it. Both hosts were rerun with a 27-second command at the default wait. Both answered "running" before it finished, and the full output was recovered afterwards.

    Left behind Live evidence from both hosts, retained with exact inputs: 27,011 ms on Codex and 27,012 ms on Claude.

    Each catch left something behind.

    A rule, an invariant, a test, a recorded limit. Every excerpt above is the record's own text, and every line number links to it.
