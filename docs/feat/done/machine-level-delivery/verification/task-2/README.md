# Claude vendor probes

Claude Code 2.1.296, Linux, 2026-11-20. The maintainer approved the temporary user-scope installation. These are observations about the terminal CLI. The optional VS Code wrapper probe was skipped because `code` was unavailable.

| Probe | Observed result |
| --- | --- |
| Local marketplace, assumption 8 | The first session ran its start hook from `catalog/releases/1.0.0`. After only the catalog entry changed, a second session ran its start hook from `2.0.0`. The first session then ran its exit hook from `1.0.0`. Each event recorded the physical path of the script invoked under `CLAUDE_PLUGIN_ROOT`. |
| Path for activation verification | After the switch, `claude plugin list --json` reported `readFromFolder` and `folderVersion` for release 2. Its `installPath` and `version` still described the release 1 cache. A fresh install of release 2 in a separate configuration also reported `readFromFolder`. That field locates the bytes to verify. The session hook events establish which release actually ran. |
| Native deny, assumption 9 | In a directory with no recorded trust for it or its ancestors, a print-mode session read the control file. The other `Read` returned a permission-settings error and appeared in `permission_denials`. The settings layer specified `disableAllHooks: true`. Print mode skips the interactive trust dialog. |
| Interactive statusline, assumption 9 | The untrusted TUI presented the trust dialog. The marker was absent with hooks on and off. Both prompts were cancelled. In the trusted control the same statusline rendered with hooks on and was absent with hooks off. The launcher cannot promise a pre-trust statusline. |
| Project plugin override, assumption 9 | With the user-scope marker disabled and the trusted project explicitly enabling it, the control session listed it and ran its hooks. Adding only `enabledPlugins[pluginId] = false` in the flag layer removed it from the session's plugin list and produced zero marker events for that session ID. |

[observations.jsonl](observations.jsonl) contains the hook log, selected CLI JSON fields, and terminal excerpts from a pseudo-terminal with cursor controls removed. Each TUI was sampled on startup (one-second initial wait). The trusted hooks-disabled session was also read through exit. The four TUI rows carry their launch session IDs. The evidence records visible output during the probe, with no latency bound for other hosts. Plugin inventory is filtered to the probe ID. The read results come from the tool stream and the final permission-denial record. Workspace trust and hook settings each affect statusline execution. [Claude statusline documentation](https://code.claude.com/docs/en/statusline#workspace-trust-required)

## Reproducing the observations

Both releases used the same hook definitions and script. Changing the catalog isolated which release path each session used. Changes to the hook definitions themselves and an explicit `/reload-plugins` were outside this run. [Vendor loading reference](https://code.claude.com/docs/en/plugins/loading#in-place-and-copied-plugins)

1. Create a private directory with `mktemp -d /tmp/kk-claude-task2-XXXXXXXX`. Run `bash fixtures.sh "$probe_dir"` with that path. The script prints the unique marketplace and plugin ID. Obtain the maintainer's agreement before registering either in the real user configuration.
2. From the scratch directory, run `claude plugin marketplace add --scope user "$probe_dir/catalog"` and `claude plugin install --scope user "$plugin_id"`. Open an interactive Claude session in `trusted/` with hooks enabled and confirm its `SessionStart` in `events.jsonl`. The trusted control inherited trust from `/tmp`.
3. With the first session open, replace `catalog/.claude-plugin/marketplace.json` with the supplied `marketplace-2.0.0.json`. Open a second session in the same directory, then exit each via `/exit`. Match start and end events by session ID. Compare the hook paths with both path fields in the matching `claude plugin list --json` entry. To reproduce the fresh-install inventory control, repeat the add, install, list and removal operations with the catalog on release 2 and `CLAUDE_CONFIG_DIR` set to a new private directory for every command. That control needs no login.
4. Put the two public marker files in a fresh directory with no trusted ancestor. This machine already trusted `/tmp`, so the run used a private `/var/tmp` directory and confirmed Claude displayed its trust dialog. Leave the folder untrusted. Run `claude -p --model haiku --strict-mcp-config --tools Read --settings "$probe_dir/layer.json" --verbose --output-format stream-json` there with the prompt `Use the Read tool separately on control-marker.txt and denied-marker.txt in the current directory. Both are harmless test fixtures. Report each tool outcome. If access is denied, stop there.` Compare the tool results by ID.
5. Start an interactive session in each workspace with `--settings "$probe_dir/status-layer.json"`, then with `layer.json`. The files differ only in the hooks-disabled setting. Look for `KK-TASK2-STATUS` and cancel any untrusted prompt with Esc.
6. Disable the marker with `claude plugin disable --scope user "$plugin_id"`. Copy `project-enabled.json` to `trusted/.claude/settings.json`. In that project compare two fresh `-p --verbose --output-format stream-json` sessions with the prompt `Reply OK without tools.` Add `--settings "$probe_dir/plugin-off.json"` to the second. Compare the startup `plugins` array and hook events for each session.
7. Close the probe sessions. From outside the project that enables the marker, run `claude plugin uninstall --scope user "$plugin_id"` and `claude plugin marketplace remove "$market"`. Check the two vendor listings and the corresponding user settings keys.

[fixtures.sh](fixtures.sh) prepares the releases, hooks and settings layers. The hook records only the event, session ID and paths, and only when launched in the trusted scratch directory. The logged-in run ended with both registrations absent. Claude marked the old cache with `.orphaned_at`. The maintainer removed that cache and both scratch directories. All three paths were verified absent. The fixture now compares physical working directories so it also logs through a symlink. That adjustment was checked locally after the vendor run.
