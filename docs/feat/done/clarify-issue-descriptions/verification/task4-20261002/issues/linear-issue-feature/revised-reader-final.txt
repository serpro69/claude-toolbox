1. The feature lets users keep working while an export is prepared, then download it later. Today, CSV creation runs synchronously, keeping users with large exports on the request until completion.

2. A user starts an export of selected rows, continues working, and later downloads those rows in their original column order.

3. The continuation and later-download outcome is accepted. The only agreed acceptance criterion is preserving the selected rows and column order. Arun proposed a background queue and download token; Mira has not approved that mechanism. The feature is not implemented.

4. Notifications are explicitly out of scope. No performance target or row cap has been agreed; the artifact does not establish those as exclusions.

5. Mira must decide how long downloads remain available before implementation. After that decision, the maintainers choose the mechanism.
