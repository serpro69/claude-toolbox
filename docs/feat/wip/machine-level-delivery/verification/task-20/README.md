# Marketplace identity transition

On 2026-11-23, disposable Linux accounts exercised Claude Code 2.1.296 and Codex CLI 0.171.0. Both vendors ran their own registration, cache, settings and hook-review code. The public switch used two Git repositories served over loopback. The managed test used the published RC4 payload and a local archive of the new implementation labelled `v0.26.0-task20.1` for the versioned installer. The tag label for that local archive was never published.

GitHub and the local tag both resolved `v0.26.0-rc.4` to `13f1ef8da99a1345e3e65d5ea3b675dc91c5ffc4` (tree `b8dac43679dd5cee8bc5435e3642b5d44dcafc40`). The earlier pilot record cites a different commit. These results identify the source used for this transition.

| Operation | Observation |
| --- | --- |
| Switch a public Git install | Both vendors added the new marketplace and installed `kk@agentstakk`. Codex also installed `kk-guard@agentstakk`. After user-scope removal of the old copies, vendor inventory showed only those final IDs. Plain Codex reviewed the public guard and reported exactly three enabled, trusted handlers under the new key. Captures `d1dca4d1-2595-4a83-b81a-a4f8b15ae1dc`, `631e046a-b4c9-4b6d-9a1a-a1c05d030a45`. |
| Stage the RC4 upgrade | Plain Codex reviewed the old guard. A noninteractive upgrade left RC4 active and the new candidate staged. Terminal confirmation persisted before the installer asked the operator to retire the pilot registrations. Claude and Codex still listed the enabled old copies. Captures `ebda4abf-fdd1-40c9-bebf-e995c05ab835`, `bf4196a6-eadc-4cb9-a5bd-f01cf6586898`. |
| Resume and review | After retiring the pilot registrations through the vendor CLIs, the already-confirmed upgrade resumed with stdin closed and no network route. Claude reported ready. The three new Codex guard handlers required review under `kk-guard@agentstakk-local`. Trusting them in plain Codex and running `kk apply` produced ready status. The existing Claude environment setting and Codex preference survived. Capture `27e597ed-5bb5-43f1-949f-ff16271d0a62`. |
| Roll back and return | Each direction ran in a new Linux network namespace with only loopback and no route. The operator removed the departing user-scope registrations before invoking the target’s own rollback. Restoring RC4 produced `kk@toolbox` for Claude and `kk@toolbox` plus `kk-guard@toolbox` for Codex. Returning to the retained candidate restored only their `@agentstakk-local` equivalents. The three previously reviewed handlers were trusted in each direction, both vendors were ready, and the journal had no pending candidate. Both vendor preferences survived. Capture `c43e80d9-edd2-4da6-971b-b5b84ced970e`. |
| Check the workspace | A project setting enabled `kk@claude-toolbox` without an old inventory entry. Status named the setting and reported Claude awaiting review. The wrapper supplied a temporary disablement and preserved the project's setting and custom environment value. Wrapped Claude and Codex sessions each returned the installed guard’s denial of a harmless read selected by a loopback model. Claude also received the release instructions. Captures `63a2fd5f-fdec-4143-9541-c3bcd434e107`, `0a65df09-ef39-42b9-aa73-038f8d30838a`, `0142acff-a86d-4c03-adc3-f31e7ae64c0b`. |
